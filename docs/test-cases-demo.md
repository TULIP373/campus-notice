# CMD 启动与源码包精简验收用例

范围：新增 AC-RUN-01、AC-PKG-02；现有业务验收仍由 docs/test-cases.md 和既有真实证据负责。本次不修改业务源码、模型逻辑或 DOCX，不调用模型、不联网、不输出私有值。用例在实现验收前由独立 test-author 定义。

## T1 中文路径与不同工作目录启动

覆盖 AC-RUN-01；关联 AC-E1-01、AC-E2-01、AC-E2-02。

前置：JDK17、已有 MySQL 运行库、私有配置、前端依赖和本地 Maven 缓存已准备。项目路径含中文、空格和括号。先记录已有服务端口与 PID。

操作：从项目以外的工作目录通过 CMD 调用完整路径的 start.cmd，并使用非交互参数；检查真实 3307、8080、5173 监听，GET /api/health 与前端首页。另人工检查双击入口的命令内容及默认打开浏览器行为。

预期：退出码 0；后端 status=UP；前端 HTTP 200；路径解析正确。失败必须明确且退出码非零，不能用仅打印成功文字代替真实启动。

证据：reports/2026-10-08/demo-launch-check.json，保存工作目录、退出码、端口/PID和HTTP结果，不保存凭据。

## T2 重复启动与停止

覆盖 AC-RUN-01；关联 AC-E1-01、AC-E2-01。

前置：本项目三个服务已经成功启动，记录三个 PID、JAR 修改时间，模型桥若已运行另记录 PID。

操作：重复运行 start.cmd；再运行 stop.cmd；检查监听和进程；最后恢复前后端。

预期：重复启动成功，已有 PID 被复用，不重构建 JAR、不多开服务。停止入口仅结束本项目前后端；MySQL 和原有模型桥继续运行，数据库内容保留。恢复后 health UP、首页200。

证据：reports/2026-10-08/demo-launch-check.json，含启动前后 PID、停止后监听与恢复结果。本用例应抓住旧后端/前端脚本将本项目已运行端口直接拒绝的问题。

## T3 冷启动保留数据库

覆盖 AC-RUN-01；关联 AC-E1-02。

前置：本项目服务和 MySQL 正常；仅在内存读取数据库的用户、角色、课程、通知计数及稳定记录摘要，不输出密码、令牌或完整记录。停掉本项目前后端和 MySQL。

操作：运行 start.cmd，复查 health 和数据库计数/摘要；检查启动链是否调用 SQL 导入或演示账号初始化。

预期：三个服务真实启动；数据库计数、摘要、原有账号均保留；启动链不调用 Init-Database、Init-DemoAccounts 或重复导入 SQL。

证据：reports/2026-10-08/demo-launch-check.json，保存计数一致布尔值及启动结果；不得保存敏感摘要原文。

## T4 首次缺少 JAR

覆盖 AC-RUN-01；关联 AC-E1-01。

前置：后端停止；所需 Maven 依赖已在本地缓存；JAR 若存在，暂存到独立测试目录并记录哈希，不修改业务源码或已跟踪文件。

操作：在 JAR 缺失状态运行启动入口，检查自动构建及后端健康；测试结束保留有效 JAR，并恢复暂存原件或核对重建结果。

预期：入口自动完成实际构建并启动，health UP；构建失败则非零退出。仅提示手动先构建、无 JAR 仍宣称成功均失败。本轮不下载依赖；缺本地依赖须如实标为未验证。

证据：reports/2026-10-08/demo-launch-check.json 与实际构建日志，保存构建退出码和健康结果。

## T5 外部进程端口冲突

覆盖 AC-RUN-01。

前置：逐个停止本项目占用目标端口的服务；用独立临时进程监听8080、5173，条件允许另测3307。临时进程不得属于项目，不修改数据库。

操作：每种端口占用分别运行 start.cmd；记录退出码和临时监听 PID 是否存活。结束后仅关闭测试自己创建的进程，恢复项目服务。

预期：明确指出冲突并非零退出；外部监听仍存活，不执行 kill/Stop-Process 去释放外部端口；8080或5173冲突应在新增其他服务前被识别。停止入口若遇外部进程同样拒绝，不结束该进程。

证据：reports/2026-10-08/demo-launch-check.json，保存占用端口、返回码、冲突消息类别和外部进程存活布尔值。本用例应捕获强杀占端口进程的错误实现。
